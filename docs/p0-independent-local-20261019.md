# 独立经营闭环、进程恢复与 CI 工件验收 · 2026-10-19

本轮把独立发布方、仓库外安装的 Worker、受限经济决策和实际经营记录接成同一条本地执行路径，并加入进程被终止后的恢复与继续经营。生产部署和既有历史记录保持不变。

运行环境为临时 Anvil `31337`、受控模型响应、固定摘要 Docker 镜像与既有独立 Arena settler；不代表新增公网 Monad 或真实供应商运行。外部安装和独立进程证明接入与角色隔离，不证明第三方团队采用或商业需求。实现入口与完整命令见[独立经营指南](INDEPENDENT-ECONOMY.md)和[消费端示例](../examples/economic-worker/README.md)。

## 验收边界

四个中断点均使用 `SIGKILL` 终止真实 Worker，再启动不同 PID 的进程：付款签名持久化但未广播；付款已上链而本地交付确认丢失；结算已上链而经营历史尚未提交；Unknown 原请求尚未解决。重启先检查原请求、原签名摘要、预算、预留和原政策，恢复观测窗口不增加付款、调用、接单或结算。

Unknown 只有在原付款全额退款及原任务经明确授权关闭后才允许继续。该关闭保留为 `authorized-failure`，不伪称 Docker 成功。退款增加现金，但不重置累计支付额度、任务次数或绝对期限。纯现金付款的链上 `PaymentRecord.taskId` 按现有合约为 `0`；任务归属由原报价、请求/付款摘要、接单与终结凭证共同绑定。

固定钱包授权目录和全生命周期独占锁在第一笔链上交易之前就绑定原 journal 与政策，另一个路径不能重开预算。模糊所有者、外地主机锁及遗留 claim 保持阻塞，需要显式核对；本轮没有实现跨主机分布式锁，也不防钱包所有者主动复制私钥或删除全部状态。

## CI 与保存范围

`review:artifacts` 的离线模式运行 `review:check` 并打包已登记证据；`--execute-local` 重新运行五项本地套件，生成独立的最新摘要、清单与 HTML 回放。工件包含检查状态、源码版本和 SHA-256 清单，失败套件保留固定诊断码；不上传 raw stdout/stderr、journal 或签名付款。`--verify` 核对文件完整性和声明范围，不代替重新执行或外部来源认证。

GitHub 两个检查任务均配置固定目录上传、失败后保留已有工件和 30 天保留期。远端检查状态以实际推送后的 GitHub run 为准；本轮只做本地验收，不触发生产部署。

主验收已运行完整 `review:check`：文档与保存证据、语义变异与隐私投影、恢复/launcher 审计、根目录与前端类型检查、既有受控经营机制以及仓库外 SDK 消费端全部通过。独立运行时/证据审查共 24 项通过。五项本地集成（经营全流程、发布方/Worker、受限控制器、独立 shadow、独立执行恢复）亦全部通过。回放的默认场景、六轮结果和 Unknown 退款关闭后继续的顺序已核对；回放投影新增因果顺序断言，未改动原始报告。

最终工件的复验命令为 `node scripts/review-artifacts.mjs --verify <absolute bundle directory>`。离线工件包含 5 个文件，本地集成工件包含 20 个文件；其中保存证据与本次新运行各自独立标注。终止的进程、临时私有目录、IPC 和本轮容器均由各 launcher 清理，报告的 cleanup 项全部通过。
